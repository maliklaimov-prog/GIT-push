# ASBIS Team 5 — каталог смартфонов

Тот же макет, что я присылал HTML-файлом, но пересобранный на настоящем стеке
референса (freshlab-v3.noface.agency): **Next.js 16 + Tailwind CSS 4 +
Lenis (инерционный скролл) + анимация появления блоков при скролле**.

## Что внутри и как это работает

```
app/
  layout.js       — корневой layout: подключает шрифты и оборачивает всё в <ReactLenis>
  page.js         — просто расставляет секции по порядку
  globals.css     — токены темы (цвета/шрифты) для Tailwind + анимации
components/
  Reveal.js       — universal "появление при скролле" (IntersectionObserver)
  Header.js       — шапка, меняет фон при скролле, мобильное меню
  Hero.js         — градиентный хиро с "парящими" телефонами на CSS-анимации
  SectionHead.js  — заголовок секции (иконка + h2 + текст), переиспользуется
  TrustStrip.js   — плашка со статистикой (7 брендов / 26 моделей / склад)
  Brands.js       — сетка карточек брендов
  Catalog.js      — фильтр по бренду + сетка карточек товаров (тут стейт)
  Steps.js        — "заказ в 3 шага"
  BuyBlock.js     — синий блок "где купить"
  Footer.js       — подвал
data/
  phones.js       — единственный файл с данными каталога (см. ниже)
```

**Почему именно так:**

- **Next.js (App Router)** — каждый раздел страницы это отдельный React-компонент
  в `components/`, а `app/page.js` их просто перечисляет. Хотите поменять
  порядок секций или убрать одну — правите один файл.
- **Tailwind CSS 4** — вместо отдельного `tailwind.config.js` (как было в v3)
  цвета и шрифты объявлены прямо в `app/globals.css` через `@theme inline`.
  Поэтому в разметке можно писать `bg-sky-light`, `text-blue-deep`,
  `font-jost` — это не встроенные классы Tailwind, а наши токены.
- **Шрифты (Jost + Manrope)** — у референса они подключены через
  `next/font/google`, который на обычном хостинге сам скачивает шрифт с
  Google при сборке и "зашивает" его в билд (без внешних запросов в
  рантайме). **В этой песочнице исходящий трафик на fonts.googleapis.com
  заблокирован политикой организации**, поэтому я подключил те же файлы
  шрифтов (тот же вариативный woff2, с поддержкой кириллицы) через npm-пакет
  `@fontsource-variable/jost` / `@fontsource-variable/manrope` — это открытые
  шрифты, просто установленные как обычная зависимость, а не скачанные "на
  лету". Результат идентичный — шрифт зашит в сборку. **На обычном сервере
  с открытым интернетом можно вернуть `next/font/google`** — так даже проще:
  открой `app/layout.js`, замени два `import "@fontsource..."` на
  `import { Jost, Manrope } from "next/font/google"`, как описано в
  https://nextjs.org/docs/app/getting-started/fonts.
- **Lenis** — библиотека плавного ("инерционного") скролла, которую я нашёл
  в коде референса (класс `lenis` на `<html>`). Подключена одной обёрткой
  `<ReactLenis root>` в `app/layout.js` — она перехватывает скролл всей
  страницы, и обычные `<a href="#section">` и `scrollIntoView` сами
  становятся плавными.
- **Появление блоков при скролле** — на референсе это самодельный хук на
  `IntersectionObserver` (класс `js-reveal`), а не Framer Motion. Я сделал
  то же самое в `components/Reveal.js`: оборачиваешь любой блок в
  `<Reveal>`, он начинает невидимым и сдвинутым вниз (класс `.reveal` в
  globals.css), а как только 15% блока попадает в область видимости —
  добавляется `.is-visible` и CSS-transition доигрывает анимацию. Проп
  `delay` устраивает "каскад" (карточки бренда появляются одна за другой).
- **Каталог/фильтр** — `Catalog.js` это единственный компонент с состоянием
  (`useState` для активного бренда). Данные берутся из `data/phones.js` —
  чтобы поменять список телефонов, цены или добавить бренд, нужно
  редактировать только этот файл, вёрстку трогать не нужно.

Собрано и проверено: `npm run build` проходит без ошибок, страница
отрендерена и провалидирована в headless-браузере (шрифты, кириллица,
фильтр по бренду, мобильная раскладка — всё работает).

## Как запустить у себя

```bash
npm install
npm run dev       # локально на http://localhost:3000, с горячей перезагрузкой
# или
npm run build && npm run start   # прод-сборка
```

Нужен Node.js 18.18+ (у меня было проверено на Node 22).

## Как "воткнуть" это в существующий сайт ASBIS

Смотря что уже есть у вас на asbis.uz:

**1. Отдельная страница/поддомен (проще всего).**
Разворачиваете этот проект как отдельное Next.js-приложение (Vercel,
собственный сервер с Node, Docker) на адресе вроде `catalog.asbis.uz` или
`asbis.uz/catalog` (через reverse-proxy в nginx: правило `location /catalog
{ proxy_pass http://localhost:3000; }`). Ссылку на неё добавляете в меню
основного сайта. Это ровно то, как обычно живут отдельные лендинги у
компаний с большим основным сайтом на другом движке.

**2. Статический экспорт — если сайт не на Next.js (WordPress, самописный PHP/HTML).**
В `next.config.mjs` добавьте `output: 'export'`, затем:
```bash
npm run build
```
Появится папка `out/` — это чистый HTML/CSS/JS без сервера Node, его можно
просто скопировать в подпапку `/catalog` на существующем хостинге (по FTP,
в WordPress через File Manager и т.п.) и залинковать оттуда. Все стили и
шрифты будут работать (next/font и Fontsource самодостаточны — файлы шрифтов
уезжают вместе со сборкой), а фильтр по бренду и анимации отработают в
браузере как обычный JS, серверная часть Next.js тут не нужна.

**3. Встроить как раздел внутри существующего Next.js-сайта.**
Если у ASBIS уже есть сайт на Next.js — просто скопируйте папки
`components/` и `data/` в тот проект, добавьте страницу
`app/catalog/page.js`, которая рендерит те же компоненты, поставьте `lenis`
и `@fontsource-variable/*` (или замените на уже используемые в проекте
шрифты) — и раздел появится как `/catalog` на основном домене.

Я бы рекомендовал вариант 2 (статический экспорт), если у вас уже есть
рабочий сайт не на Next.js — меньше всего телодвижений на стороне хостинга.
